# Контекст дипломної роботи

Цей файл ведеться автоматично під час розробки і містить матеріал для написання дипломної роботи.
Після кожної значущої зміни в проєкті — сюди додається опис рішення, обґрунтування вибору технологій тощо.

---

## Тема та мета

**Тема:** Веб-застосунок для управління торговою точкою

**Мета:** Розробити повноцінний веб-застосунок що дозволяє власнику або менеджеру торгової точки вести облік продажів, контролювати інвентар складу та переглядати аналітику у зручному інтерфейсі.

**Практична цінність:** Замінює ручний облік в Excel або зошиті на структурований цифровий інструмент з реальною базою даних, авторизацією та візуалізацією даних.

---

## Стек технологій

### Frontend
- **Next.js 16 (App Router)** — React-фреймворк з серверним рендерингом. Обраний через вбудований роутинг, підтримку TypeScript та оптимізацію продуктивності.
- **React 19** — бібліотека для побудови UI на основі компонентів.
- **TypeScript** — статична типізація що зменшує кількість помилок під час розробки.
- **Tailwind CSS v3** — utility-first CSS фреймворк для швидкої стилізації без написання окремих CSS файлів.
- **shadcn/ui** — набір готових доступних UI-компонентів побудованих на Radix UI. Не є npm-пакетом — компоненти копіюються в проєкт і повністю кастомізуються.
- **Recharts** — бібліотека для побудови графіків на основі React та SVG.

### Backend / Інфраструктура
- **Supabase** — Backend-as-a-Service на базі PostgreSQL. Надає: базу даних, REST і Realtime API, авторизацію користувачів, безкоштовний хостинг. Обраний як альтернатива власному серверу що спрощує розробку і дозволяє зосередитись на бізнес-логіці.

### Інструменти розробки
- **ESLint** — статичний аналіз коду для виявлення помилок і дотримання стилю.
- **date-fns v3** — бібліотека для роботи з датами. Обрана через модульність (імпортуються тільки потрібні функції) та підтримку локалізації (українська мова для відображення дат).

## Архітектура застосунку

### Маршрутизація
Застосунок використовує Next.js App Router з route group `(dashboard)` що об'єднує всі захищені сторінки:

```
/login        — вхід в систему
/dashboard    — головна сторінка з графіками та KPI
/sales        — облік продажів (CRUD)
/inventory    — управління інвентарем (CRUD)
/reports      — звіти з фільтрацією по датах
```

Неавторизований користувач автоматично перенаправляється на `/login`.

### Управління станом
Глобальний стан реалізований через React Context (`StoreProvider`). Провайдер підключений на рівні layout захищеної зони і надає всім дочірнім компонентам доступ до даних та CRUD-операцій без зовнішніх бібліотек (Redux, Zustand тощо).

### Шари даних
1. **`lib/store.ts`** — типи даних, функції агрегації (підрахунок виручки, середнього чеку тощо)
2. **`lib/store-context.tsx`** — React Context з CRUD-операціями
3. **Supabase** — персистентне сховище (буде підключено)

## Журнал рішень

### 2026-04-28 — Початкова версія
Проєкт згенеровано через v0 (AI-генератор інтерфейсів від Vercel). Базова структура включає всі сторінки та UI-компоненти. Дані на цьому етапі мокові — генеруються в пам'яті при завантаженні.

**Вирішені проблеми при налаштуванні:**
- Конфлікт `date-fns@4` з `react-day-picker@8` — понижено до `date-fns@3`, оновлено `react-day-picker` до v9
- `react-day-picker` v9 має інший API `classNames` — оновлено `calendar.tsx` під новий формат
- Видалено зайву залежність `@tailwindcss/postcss` (для Tailwind v4) що конфліктувала з конфігом v3
